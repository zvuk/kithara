## 1. Архитектура: Asset Store и формат данных

- 🟢 **АШ** — Объединить Asset Store в один универсальный инстанс. Сделано: `Ctx` полностью стёрт до trait-объекта (`ProcessCtx`), обработка (декрипт HLS) ездит per-acquire, а не задаётся при сборке стора. Обёртка `HlsStore` удалена, приложение держит один `Arc<AssetStore>` для file и HLS, скоупы разруливают именование/маршрутизацию (проверено `Arc::ptr_eq`).
- 🟢 **АШ** — Добавить trait (делегат) для Scope, по аналогии с паттерном делегатов в Objective-C. Стор должен спрашивать у вызывающего кода, как именовать файлы на диске, чтобы строить иерархию внутри папки трека. Сделать дефолтную реализацию «как сейчас», а опционально — красивую раскладку (MP3 как файл; для HLS — папки low/high quality и т.д.). Сейчас всё свалено в кучу с хэш-именами по параметрам. Частично: trait `AssetScopeDelegate` + `DefaultAssetScopeDelegate` («как сейчас») есть; опциональная «красивая раскладка» — ещё нет.
- 🟢 **АШ** — Кэшировать артефакты анализа (BPM, карта битов) рядом с артефактами трека. Уже переделано: благодаря иерархичному (scoped) Asset Store получается почти бесплатно.
- 🔴 **АШ** — Изобрести собственный формат файла для аналитических данных (аналог Ableton `.als`): складывать туда всё, что анализируем. Использовать уже подключённый RT/serde (не плодить лишнего), сделать отдельный микрокрейт, отвечающий за парсинг. Выработать общую иерархичную доменную модель (сейчас наивно — отдельные файлы).
- 🔴 **АШ** — Задокументировать структуру генерируемых при анализе данных, чтобы часть работы можно было вынести на сервер: через API получать точный BPM и карту битов в виде JSON (а не бинарного формата) и класть на диск.
- 🟢 **АШ** — Убрать дублирующиеся пути конфигурации Asset Store (`StoreOptions`): через конфиг должен передаваться только один параметр — либо готовый инстанс, либо его конфиг (если инстанс создаётся внутри). Не допускать двух и более путей для одних и тех же данных. Сделано вместе с объединением стора: приложение строит один `AssetStore` и передаёт готовый `Arc<AssetStore>` в file и HLS (`HlsConfig.asset_store: Option<Arc<AssetStore>>`); коллизия `_index/` от двух инстансов на одном `cache_dir` устранена.

## 2. Анализ трека (BPM / beatgrid / waveform) и перенос на уровень SDK

- 🔴 **АШ** — Первично проинтегрировать определение BPM и сетки (beatgrid), проверить, что сетка определяется правильно. Это приоритетная фича. Реальная продуктовая потребность (нужно для сведения; есть в целях на конец года).
- 🔴 **АШ** — Перенести анализ с уровня приложения на уровень SDK. Сейчас воркер живёт в самом приложении; нужно, чтобы интеграторы (iOS, Android) могли использовать функциональность — в т.ч. построение waveform, которое у них раньше не получилось.
- 🔴 **АШ** — Переработать воркер анализа: сделать его кооперативным, с очередью на случай нескольких треков в плейлисте.
- ❓ **АШ/ПЛ** — Определиться, какой уровень качества HLS анализируется. Сейчас риск дублирования: играет одно качество, а анализатор триггерит загрузку другого. Решить при переработке воркера: анализировать то, что лежит на диске; если ничего нет — продумать, что скачивать и как это согласуется с плеером.
- ❓ **АШ/ПЛ** — Ввести лимит (cap) на фоновый анализ треков. Сейчас лимита нет: при большом плейлисте и ограниченном кэше происходит вытеснение и бесконечная перезагрузка. Нужен порог, чтобы остановиться и не грузить лишнее.

## 3. Интерфейс и визуализация

- 🔴 **АШ** — Вместо двух режимов интерфейса сделать один адаптивный: при расширении окна показываем больше деталей, при сужении — компактный вид. UI делать без фанатизма (приложение — «боевой полигон» для тестирования фич), стилизацию отдавать агенту.
- 🔴 **АШ** — Waveform: масштабирование вплоть до сэмпла, чтобы на большом увеличении была видна синусоида. Сейчас максимум ~16×, нужно больше.
- 🟡 **АШ** — Прикрутить waveform к реальному плееру (сейчас отрисовываются синтетические/случайные данные).
- 🔴 **АШ** — Bit Slicer: добавить режим зацикливания слайса (loop) — слайс играет до конца и сразу начинается заново, чтобы проверять работу плеера в цикле.
- 🔴 **АШ** — Перенести выбор/старт слайса на саму визуализацию waveform: клик по дорожке → проигрывание с этого места/слайса. Сейчас выбор происходит в панели Bit Slicer; продумать, как обыграть это на шкале (сейчас клик делает seek).
- 🔴 **АШ** — Waveform: цветовое кодирование по частотам (RGB по частотному спектру, как в Traktor/Rekordbox: низкие → красный, высокие → синий). Сделать привычный для диджеев вид; опционально — кнопка переключения режима отображения. Ориентир — Traktor DJ и Rekordbox; посмотреть на визуализацию сетки в Traktor / Ableton.
- 🔴 **АШ** — Cue-points (закладки) и Loops — диджейские фичи как в Traktor (дальняя перспектива, но нужны).
- 🟡 **АШ** — Time-stretch применять к каждому слайсу отдельно, а не к треку целиком. BitZ в интерфейс запушен, осталось «прокинуть».
- 🟢/🔴 **АШ** — Тайм-стретч: оставить только Signal Smith (переключатель алгоритмов убрать). Кнопки с процентами (градации шкалы) можно убрать позже — мешать не мешают, достаточно одного слайдера.
